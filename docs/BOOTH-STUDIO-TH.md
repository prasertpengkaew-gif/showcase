# AR Photo Booth Studio — คู่มือสำหรับผู้ให้เช่าระบบ (TheNerdStudio)

ระบบตู้ถ่ายรูป AR ที่คุณตั้งค่าให้ลูกค้า (ออแกไนซ์) ทุกงาน แขกถ่ายรูปที่ตู้ แล้วสแกน **QR** เพื่อดาวน์โหลดรูปลงมือถือตัวเอง

> เอกสารนี้ครอบคลุม **ขั้นที่ 1**: คุณเป็นคนตั้งค่างานและเปิดตู้ให้ลูกค้า ยังไม่มีแดชบอร์ดให้ลูกค้าเข้าใช้เอง และยังไม่มีจอรวมรูปสดหรือเครื่องพิมพ์รูป

## ภาพรวม

```
 ตู้ที่หน้างาน (iPad / โน้ตบุ๊ก / จอทัช)          Supabase                      มือถือของแขก
 /booth/<ชื่องาน>?k=<โทเคน>      ─ถ่ายรูป→  ฐานข้อมูล + ที่เก็บรูป  ←สแกน QR─  /p/<รหัสรูป>
   • ติดตามใบหน้า/วางพร็อพในเครื่อง           (ลบอัตโนมัติเมื่อหมดอายุ)          โหลด / แชร์ / ลบรูปตัวเอง
   • ถ้าเน็ตหลุด รูปรอในเครื่องแล้วอัปโหลดทีหลัง
```

- **ตู้** ใช้ลิงก์ส่วนตัวที่มีโทเคนลับ (คุณเป็นคนออกให้) การประมวลผลใบหน้าทำในเครื่อง ไม่มีค่า AI ต่อรูป
- **แขก** เปิดลิงก์จาก QR ได้เลย ไม่ต้องโหลดแอป ลิงก์เดายาก (รหัส 12 ตัวอักษรสุ่ม) และหมดอายุเอง
- **คุณ** ใช้สคริปต์ `scripts/booth-admin.mjs` สร้างงาน ออกลิงก์ ส่งออกรูปให้ลูกค้า และลบรูปหมดอายุ

## 1. ตั้งค่าระบบครั้งแรก (ทำครั้งเดียว)

### 1.1 สร้างโปรเจกต์ Supabase

1. สมัคร/เข้าสู่ระบบที่ <https://supabase.com> แล้วกด **New project** (เลือกภูมิภาคใกล้ไทย เช่น Singapore)
2. เมื่อสร้างเสร็จ เปิด **SQL Editor** → **New query** แล้ววางเนื้อหาไฟล์ [`supabase/migrations/20261020000000_booth_studio.sql`](../supabase/migrations/20261020000000_booth_studio.sql) ทั้งไฟล์ แล้วกด **Run** (รันซ้ำได้ ไม่เสียหาย)
3. ไปที่ **Project Settings → API** แล้วคัดลอกค่า 3 อย่าง:
   - **Project URL** (เช่น `https://abcd1234.supabase.co`)
   - **anon public key** — ใส่ในเว็บได้ ปลอดภัย เพราะสิทธิ์ถูกควบคุมที่ฐานข้อมูล
   - **service_role key** — ⚠️ **ห้ามใส่ในเว็บ ห้ามส่งให้ใคร (รวมถึงในแชทกับ AI)** ใช้เฉพาะในเครื่องของคุณเท่านั้น

### 1.2 ต่อเว็บเข้ากับ Supabase

ใน Vercel: **Project → Settings → Environment Variables** เพิ่ม

| ชื่อ | ค่า |
| --- | --- |
| `VITE_SUPABASE_URL` | Project URL |
| `VITE_SUPABASE_ANON_KEY` | anon public key |
| `VITE_PUBLIC_URL` | (ไม่บังคับ) โดเมนที่จะอยู่ใน QR ถ้าต่างจากโดเมนที่ตู้เปิด |

แล้ว **Redeploy** ตอนนี้ `/booth/demo` จะไม่ใช่โหมดเดโมอีกต่อไป (โหมดเดโมใช้เฉพาะตอนไม่ได้ตั้งค่า Supabase)

### 1.3 ตั้งค่าเครื่องของคุณสำหรับสคริปต์แอดมิน

สร้างไฟล์ `.env.booth` ในโฟลเดอร์โปรเจกต์ (ไฟล์นี้ถูก git ละเว้นอยู่แล้ว):

```
SUPABASE_URL=https://abcd1234.supabase.co
SUPABASE_SERVICE_ROLE_KEY=ใส่-service-role-key-ที่นี่
SITE_URL=https://ชื่อเว็บของคุณ.vercel.app
```

ต้องใช้ Node.js 18 ขึ้นไป ลองรัน `node scripts/booth-admin.mjs list` ถ้าขึ้น "No events yet" แปลว่าเชื่อมต่อสำเร็จ

## 2. เตรียมงานให้ลูกค้า

### 2.1 ขอข้อมูลจากลูกค้า

- ชื่องาน, วัน-สถานที่ หรือแฮชแท็ก (บรรทัดที่สองบนกรอบ)
- โลโก้ (PNG พื้นใส) และสีหลักของแบรนด์
- ช่วงเวลาจัดงาน, จำนวนรูปที่คาดว่าจะถ่าย (ใช้ตั้งเพดาน)
- ต้องการกรอบสำเร็จรูปของเรา หรือกรอบที่ดีไซเนอร์ของเขาทำเอง
- แนวภาพ: **แนวตั้ง (2:3)**, **แนวนอน (3:2)** หรือ **จัตุรัส (1:1)**

### 2.2 กรอบรูปของลูกค้า (ถ้ามี)

ให้ดีไซเนอร์ใช้เทมเพลตใน [`docs/booth-templates/`](booth-templates) เป็นแนวทาง:

| แนวภาพ | ขนาด | ไฟล์เทมเพลต |
| --- | --- | --- |
| แนวตั้ง 2:3 | 1200 × 1800 px | `frame-portrait-1200x1800.png` |
| แนวนอน 3:2 | 1800 × 1200 px | `frame-landscape-1800x1200.png` |
| จัตุรัส 1:1 | 1400 × 1400 px | `frame-square-1400x1400.png` |

- ส่งเป็น **PNG พื้นหลังโปร่งใส** ขนาดไม่เกิน 5 MB
- **เว้นกลางภาพ (วงรีสีแดงในเทมเพลต) ไว้ให้โล่ง** เพราะเป็นตำแหน่งใบหน้า
- ตัวหนังสือสำคัญควรอยู่ในกรอบ **Safe margin 5%** (เส้นประสีน้ำเงิน)
- ถ้าสัดส่วนไม่ตรง ระบบจะ **ครอป** ให้เต็มภาพ สคริปต์จะเตือนถ้าสัดส่วนคลาดเคลื่อนเกิน 2%
- ถ้าไม่มีกรอบของลูกค้า ใช้กรอบสำเร็จรูปได้: `neon` (งานเปิดตัว), `gold` (งานกาลา/งานแต่ง), `fest` (เทศกาล) ซึ่งพิมพ์ชื่องานและบรรทัดที่สองให้เอง

### 2.3 สร้างไฟล์งาน

คัดลอก [`events/example.json`](../events/example.json) เป็นชื่อใหม่ (เช่น `events/acme-launch.json`) แล้วแก้ ไฟล์ในโฟลเดอร์ `events/` ถูก git ละเว้น (ยกเว้นตัวอย่าง) เพื่อไม่ให้ข้อมูลลูกค้าหลุดเข้า repository

```json
{
  "slug": "acme-launch",
  "name": "Acme Launch Night",
  "startsAt": "2026-11-01T10:00:00+07:00",
  "endsAt": "2026-11-01T23:59:00+07:00",
  "maxPhotos": 2000,
  "retentionDays": 30,
  "booth": {
    "language": "th",
    "aspect": "portrait",
    "subtitle": "1 พ.ย. 2569 · กรุงเทพฯ",
    "frame": { "kind": "image", "file": "./acme/frame.png" },
    "logoFile": "./acme/logo.png",
    "accent": "#E11D48",
    "props": ["glasses", "crown", "none"],
    "defaultProp": "glasses",
    "countdown": 3,
    "smileToSnap": true,
    "reviewSeconds": 25
  }
}
```

| ค่า | ความหมาย |
| --- | --- |
| `slug` | ชื่อในลิงก์ (a–z, 0–9, `-` ยาว 3–40) |
| `startsAt` / `endsAt` | ตู้เปิดใช้งานเฉพาะช่วงนี้ รูปที่ค้างอัปโหลดยังส่งได้อีก 3 วันหลังจบงาน |
| `maxPhotos` | เพดานจำนวนรูป (เว้นว่าง = ไม่จำกัด) กันค่าที่เก็บรูปบานปลาย |
| `retentionDays` | เก็บรูปกี่วันนับจากถ่าย (1–365) แล้วลบอัตโนมัติ |
| `frame` | `{"kind":"image","file":"..."}` กรอบของลูกค้า หรือ `{"kind":"preset","theme":"neon"}` |
| `aspect` | `portrait` / `landscape` / `square` |
| `props` | พร็อพที่แขกเลือกได้: `glasses`, `crown`, `none` |
| `countdown` | นับถอยหลัง 1–10 วินาที |
| `smileToSnap` | ยิ้มค้างแล้วถ่ายเองโดยไม่ต้องกดปุ่ม |
| `reviewSeconds` | QR ค้างบนจอกี่วินาทีก่อนรีเซ็ตให้แขกคนถัดไป (8–120) |
| `consent` | (ไม่บังคับ) ข้อความความเป็นส่วนตัวที่ตู้ ถ้าไม่ใส่จะใช้ข้อความมาตรฐาน |
| `language` | ภาษาที่ตู้: `th` หรือ `en` |

### 2.4 สร้างงานและรับลิงก์ตู้

```bash
node scripts/booth-admin.mjs create events/acme-launch.json
```

สคริปต์จะอัปโหลดกรอบและโลโก้ให้เอง แล้วพิมพ์ **ลิงก์ตู้** ออกมา เช่น

```
https://ชื่อเว็บ.vercel.app/booth/acme-launch?k=3f9a…
```

> ลิงก์นี้คือ "กุญแจ" ของตู้ ใครมีลิงก์ก็เปิดตู้และอัปโหลดรูปเข้างานนี้ได้ จึงให้เฉพาะคนที่ติดตั้งตู้ ถ้าลิงก์หลุดสั่ง `rotate-token` ได้ (ดูหัวข้อ 5)

แก้ไขงานภายหลัง: แก้ไฟล์ JSON แล้วรัน `node scripts/booth-admin.mjs update events/acme-launch.json` (ลิงก์เดิมยังใช้ได้ ตู้จะได้ค่าใหม่เมื่อรีโหลดหน้า)

## 3. ติดตั้งตู้ที่หน้างาน

### อุปกรณ์ที่แนะนำ
- **iPad / แท็บเล็ต Android** บนขาตั้ง หรือ **โน้ตบุ๊ก/จอทัช + เว็บแคม** ที่ตั้งตามแนวภาพของงาน
- ไฟส่องหน้าสม่ำเสมอ ไม่ย้อนแสง (ช่วยให้ติดตามใบหน้าและยิ้มเพื่อถ่ายแม่นขึ้นมาก)
- อินเทอร์เน็ตสำรอง (ฮอตสปอตมือถือ) เผื่อ Wi-Fi ของงานไม่เสถียร

### ขั้นตอน
1. ปิดการล็อกหน้าจออัตโนมัติ (iPad: *Settings → Display & Brightness → Auto-Lock → Never*) และเสียบชาร์จ
2. เปิดลิงก์ตู้ด้วย **Safari** (iPad) หรือ **Chrome** แล้วกด **เริ่มตู้ถ่ายรูป** อนุญาตการใช้กล้อง ตู้จะเปิดเต็มจอและกันหน้าจอดับ
3. **ทดลองถ่าย 1 รูป** แล้วใช้มือถือสแกน QR ตรวจว่าเปิดรูปได้
4. iPad: เปิด **Guided Access** (*Settings → Accessibility → Guided Access*) แล้วกดปุ่มด้านข้างสามครั้งเพื่อล็อกเครื่องให้อยู่ในหน้าตู้ ไม่ให้แขกออกไปแอปอื่น
5. ถ้าเชื่อมอินเทอร์เน็ตตอนเริ่มได้ ตู้จะจำค่าตั้งไว้ รีโหลดตอนเน็ตหลุดก็ยังเริ่มได้

### เมนูเจ้าหน้าที่
**กดค้างที่มุมขวาบนของจอ 1–2 วินาที** (หรือกด `Shift + S` บนคีย์บอร์ด) จะเห็น: จำนวนรูปที่ถ่าย, คิวอัปโหลด, คำเตือนถ้ารูปเต็มโควตา/โหลดกรอบไม่ได้, ปุ่มเต็มจอ, สลับกล้อง, โหลดการตั้งค่าใหม่, หยุดตู้

**ป้ายมุมซ้ายล่าง** แสดงตลอดว่า "บันทึกรูปครบทุกรูปแล้ว" หรือมีกี่รูปรออัปโหลด

## 5. หลังงาน

```bash
node scripts/booth-admin.mjs stats acme-launch      # สรุปจำนวนรูป
node scripts/booth-admin.mjs export acme-launch ./acme-photos   # ดาวน์โหลดรูปทั้งหมด + index.csv ส่งมอบลูกค้า
node scripts/booth-admin.mjs close acme-launch      # ปิดตู้ (รูปเดิมยังเปิดได้จนหมดอายุ)
```

- ส่งมอบรูปให้ลูกค้าเป็นโฟลเดอร์ (บีบอัดเป็น zip ด้วยเครื่องมือของระบบปฏิบัติการ) พร้อม `index.csv`
- `rotate-token <ชื่องาน>` ออกลิงก์ตู้ใหม่และยกเลิกลิงก์เดิม ใช้เมื่อลิงก์หลุด หรือหลังจบงานที่ใช้ซ้ำชื่อเดิม
- `list` แสดงทุกงานพร้อมจำนวนรูป

### ลบรูปที่หมดอายุ
รูปจะ **ถูกซ่อนจากแขกทันทีเมื่อหมดอายุหรือแขกลบ** แต่ไฟล์จริงถูกลบเมื่อรัน

```bash
node scripts/booth-admin.mjs purge            # ลบจริง
node scripts/booth-admin.mjs purge --dry-run  # ดูก่อนว่าจะลบกี่รูป
```

ตั้งให้รันทุกสัปดาห์ หรือใช้ GitHub Actions ที่เตรียมไว้ใน [`.github/workflows/purge-booth-photos.yml`](../.github/workflows/purge-booth-photos.yml) (รันทุกวัน ต้องเพิ่ม secrets `SUPABASE_URL` และ `SUPABASE_SERVICE_ROLE_KEY` ใน GitHub ถ้าไม่อยากเก็บ service key ไว้ที่ GitHub ให้ลบไฟล์นี้แล้วรันเองด้วยมือ)

## 6. ข้อมูลส่วนบุคคล (PDPA) — สิ่งที่ต้องรู้ก่อนเปิดให้เช่า

รูปใบหน้าและข้อมูลที่เกี่ยวกับตัวบุคคลเป็นข้อมูลส่วนบุคคล ระบบมีส่วนช่วยดังนี้ แต่ **ความรับผิดชอบทางกฎหมายต้องให้ที่ปรึกษากฎหมายของคุณตรวจก่อนเปิดขาย**

**ที่ระบบทำให้แล้ว**
- ตู้แสดงข้อความแจ้งการเก็บรูปและระยะเวลา (แก้ได้ที่ `consent`) ก่อนแขกถ่าย
- การติดตามใบหน้าทำในเครื่อง ไม่อัปโหลดวิดีโอ และ **ไม่ระบุตัวตน** ว่าเป็นใคร
- รูปถูกอัปโหลดต่อเมื่อแขกถ่ายรูปเท่านั้น และลิงก์เดายาก ดูได้เฉพาะคนที่มีลิงก์
- กำหนดอายุการเก็บ (`retentionDays`) ลบอัตโนมัติด้วย `purge`
- แขกลบรูปตัวเองได้ทันทีจากหน้ารูป
- หน้ารูปและตู้ไม่ถูกจัดทำดัชนีโดยเครื่องมือค้นหา (`noindex`)

**ที่คุณต้องทำเอง**
- ทำข้อตกลงกับออแกไนซ์ว่าใครเป็น "ผู้ควบคุมข้อมูล" และใครเป็น "ผู้ประมวลผล" (โดยทั่วไปออแกไนซ์/เจ้าของงานเป็นผู้ควบคุม คุณเป็นผู้ประมวลผล) รวมถึงระยะเวลาเก็บรูปและการส่งมอบ/ลบรูปหลังงาน
- ถ้าลูกค้าจะเก็บอีเมลหรือ LINE ของแขก (ยังไม่มีในขั้นที่ 1) ต้องมีความยินยอมแยกต่างหากและชัดเจน
- ตรวจสอบว่ากรอบ โลโก้ และภาพที่ลูกค้าส่งมา เป็นของเขาหรือได้รับอนุญาตแล้ว
- ที่เก็บข้อมูล Supabase อยู่นอกประเทศไทย (ตามภูมิภาคที่เลือก) ควรระบุในนโยบายความเป็นส่วนตัว

---

## 7. ความปลอดภัย (สรุป)

- เบราว์เซอร์ถือแค่ anon key ซึ่ง **อ่าน/เขียนตารางข้อมูลโดยตรงไม่ได้** ทุกอย่างผ่านฟังก์ชันที่ตรวจสิทธิ์ที่ฐานข้อมูล (ทดสอบกับ Postgres จริงด้วย `npm run test:sql`)
- ตู้ต้องมีโทเคนลับของงานนั้น จึงจะโหลดค่าตั้งและอัปโหลดรูปได้ และอัปโหลดได้เฉพาะ path ที่ลงทะเบียนไว้แล้วเท่านั้น (เขียนทับหรือแอบอัปโหลดไฟล์อื่นไม่ได้) ที่เก็บรูปแสดงรายการไม่ได้
- ถ้าลิงก์ตู้หลุด: `rotate-token` ทันที ผู้ไม่หวังดีที่มีโทเคนทำได้แค่ส่งรูปเข้างานนั้น (ถูกจำกัดด้วย `maxPhotos`) อ่านรูปของแขกไม่ได้
- **ข้อจำกัดที่ยังไม่ได้ทำ:** ยังไม่มีการจำกัดอัตราการเรียก (rate limit) ที่ระดับฐานข้อมูล ถ้าต้องรองรับงานสาธารณะขนาดใหญ่ควรเปิดคุณสมบัติจำกัดอัตราของ Supabase เพิ่ม

## 8. แก้ปัญหาเบื้องต้น

| อาการ | สาเหตุที่พบบ่อย |
| --- | --- |
| "ลิงก์ตู้ถ่ายรูปนี้ใช้ไม่ได้" | ลิงก์ไม่ครบ (ขาด `?k=…`), งานยังไม่เริ่ม/จบแล้ว, ถูก `close`, หรือถูก `rotate-token` |
| "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" | อินเทอร์เน็ตหลุดตอนเปิดครั้งแรก (ครั้งต่อไปที่เคยเปิดสำเร็จแล้วจะเริ่มจากค่าที่จำไว้) หรือยังไม่ได้ตั้ง `VITE_SUPABASE_*` ใน Vercel |
| ตู้ขึ้น "โหมดเดโม" | ยังไม่ได้ตั้ง `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` หรือยังไม่ได้ Redeploy |
| QR สแกนแล้วขึ้น "รูปของคุณใกล้เสร็จแล้ว" นาน | รูปยังอยู่ในคิวของตู้ (ดูป้ายมุมซ้ายล่าง) ตรวจอินเทอร์เน็ตของตู้ |
| กรอบของลูกค้าไม่ขึ้น | เมนูเจ้าหน้าที่จะแจ้ง "โหลดกรอบไม่ได้" ตรวจไฟล์ PNG และรัน `update` ใหม่ |
| ยิ้มแล้วไม่ถ่าย | แสงไม่พอ/ย้อนแสง หรือยิ้มไม่ถึง 0.7 วินาที ให้ใช้ปุ่มถ่ายรูปแทน |
| `purge` ขึ้น error | ตรวจว่า service key ถูกต้องและไม่ได้หมดอายุ รันซ้ำได้ ไม่เสียหาย |

## 9. ทดสอบระบบ

```bash
npm run test:sql      # ฐานข้อมูล: สิทธิ์ของ anon key, โควตา, หมดอายุ, นโยบายอัปโหลด (Postgres จริงผ่าน PGlite)
npm run test:admin    # สคริปต์แอดมิน: สร้างงาน ลิงก์ ส่งออก ลบรูป (เซิร์ฟเวอร์จำลอง)
npm run test:e2e      # เบราว์เซอร์: ตู้ → อัปโหลด → QR → หน้ารูปของแขก → ลบ, คิวตอนเน็ตหลุด, โควตาเต็ม, กรอบของลูกค้า, โหมดเดโม
```

**สิ่งที่การทดสอบเหล่านี้ยังไม่ครอบคลุม:** การทำงานกับ Supabase ตัวจริง (ใช้เซิร์ฟเวอร์จำลองที่ทำตามสัญญาเดียวกัน) และอุปกรณ์จริง (iPad รุ่นเก่า, การเปิดต่อเนื่องหลายชั่วโมง) ควรทดลองเต็มระบบกับโปรเจกต์ Supabase จริงและอุปกรณ์จริงอย่างน้อยหนึ่งรอบ (รวมการถ่ายต่อเนื่อง 1–2 ชั่วโมง) ก่อนใช้กับงานจริง
